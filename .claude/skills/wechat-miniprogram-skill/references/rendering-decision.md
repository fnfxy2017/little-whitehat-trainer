# 渲染方案决策树（详细版）

> 本文回答：婉婉冒险的每一个 UI 元素，应该用 DOM、Canvas 还是 WebView？

## 三种渲染方案的本质区别

| 方案 | 谁渲染 | 适合什么 | 与 H5 对应 |
|---|---|---|---|
| **WXML/WXSS (Skyline)** | 渲染引擎 | 静态 UI、表单、列表、文本、有限动画 | div + CSS |
| **Canvas 2d** | GPU/CPU 绘制 | 自由像素、粒子、大量自定义图形 | `<canvas>` |
| **web-view** | 内置浏览器 | 已有 H5 完整页面 | iframe |

## 通用原则

> 能用 DOM 解决的，永远不要用 Canvas。

小程序 Canvas **不是** Web Canvas 的简单替代。每次 Canvas 状态都要从逻辑层穿越到渲染层，重绘开销 + 通信开销 + 序列化开销叠加，往往比 DOM 慢。Canvas 真正的优势只在两个场景：

1. 元素**数量级太大**（几百个粒子）做不到一个一个 view
2. 元素需要**像素级自由位置 + 高频更新**

婉婉冒险里满足这两个条件的元素几乎没有。

## 婉婉冒险逐元素映射

| H5 中的元素 | 小程序方案 | 理由 |
|---|---|---|
| 关卡选择网格 | scroll-view + view 网格 | 静态列表 |
| 关卡背景插画 | image 组件 | 单图，不需要动 |
| 介绍弹窗 | view + 遮罩 | 静态层级 |
| 对话气泡 | Component (view + text) | 频繁更新但范围小 |
| 跳过按钮「跳过 »」 | button / view bindtap | 标准交互 |
| 卡片库（左侧/底部栏） | view + flex 布局 | 列表 |
| 单张卡片 | Component | 拖动会高频更新 |
| 队列槽位 | view 横向排列 | 静态容器 |
| 卡片拖拽中 | Worklet 改 transform | 唯一拖拽方案 |
| 婉婉角色 | **方案 A**: image + transform 动画 | 优先 |
| 婉婉角色 | **方案 B**: canvas type="2d" | 仅当方案 A 不流畅 |
| 通关粒子/烟花 | canvas type="2d" | 粒子数 > 20 时 |
| 步数计数器 | text | 数字而已 |

## 决策流程（任何新元素来了都问这五个问题）

### Q1: 它是文字、按钮、列表，或者只显示一张图？
→ **DOM**。不要犹豫。Skyline 下流畅得很。

### Q2: 它需要拖拽、滑动、缩放（用户手指连续操作）？
→ **DOM + Worklet**。Worklet 的 transform 跑在渲染线程，等同于原生丝滑。
→ 见 `skyline-and-worklet.md`

### Q3: 它是大量重复的小图形（≥20 个），且每帧都在动？
→ **Canvas type="2d"**。用 `canvas.requestAnimationFrame` 自循环。
→ 见 `canvas-2d-rules.md`

### Q4: 它是一个完整的 H5 页面，赶时间不想重写？
→ **web-view**。但有限制：不能调 wx.* API、不能与小程序双向通信（除了简单的 postMessage）、登录态要重新打通。**婉婉冒险不建议走这条**，因为后续要支持微信支付/订阅消息时迁移成本反而更高。

### Q5: 它是一个 3D 场景或大型物理引擎？
→ **改用小游戏（minigame）**，整个项目从「小程序」切换到「小游戏」类型。婉婉冒险用不到。

## 婉婉舞台移动：A vs B 实测决策

> 这是项目里唯一可能需要 Canvas 的地方，建议先实现 A，跑不动再切 B。

**方案 A：纯 DOM + Worklet 动画**
- 婉婉是一张 image，绝对定位
- 移动：Worklet 改 transform: translate3d(x, y, 0)
- 沿队列前进 = 一段段平移动画（每条指令一段）
- 优点：与卡片、队列、对话框是同一渲染体系，无需在两个世界之间同步
- 已知风险：如果加上多个粒子特效或者背景滚动，可能掉帧

**方案 B：婉婉所在区域用 Canvas**
- 把"舞台"区域（婉婉走动那一块）做成一个 `<canvas type="2d">`
- 卡片、队列、对话框依然是 DOM
- 婉婉、地图格、粒子全部在 Canvas 里画
- 优点：高密度动画稳定 60 FPS
- 代价：Canvas 与 DOM 是两个世界，需要建立坐标系映射；婉婉位置数据需要在 Canvas 内部维护，外面 DOM 拿不到

**判断标准（接孩子真机测试时看）：**
- 方案 A 帧率 ≥ 30 FPS 就接受
- 方案 A 帧率 < 30 FPS 或者孩子能看出"卡"，切方案 B

## 严禁的混合做法

- ❌ 用 view + setData 改 left/top 做帧动画 — H5 思维迁移过来的最大错误
- ❌ 用 Canvas 画对话气泡（字体渲染、自适应、点击区域全要重写）
- ❌ 用 Canvas 画按钮（无障碍、点击反馈全没了）
- ❌ 一半 Canvas 一半 DOM 还互相 z-index 穿透 — 小程序 Canvas 是原生组件，层级处理特殊，详见小程序原生组件文档
